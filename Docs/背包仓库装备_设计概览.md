# 背包系统 + 仓库系统 + 人物装备系统 — 设计概览

> Unity 2D 横板动作项目。本文档为设计概览，不写具体代码实现。
> 标注「程序实现」「编辑器配置」以区分执行角色。

---

## 一、系统定位与关系总览

```
┌─────────────────────────────────────────────────────┐
│                    物品数据层                        │
│  ItemSO (模板) ──→ ItemInstance (运行时实例)         │
│  静态配置表           动态持有状态                    │
└────────┬──────────────┬──────────────┬──────────────┘
         │              │              │
    ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
    │  背包    │   │  仓库    │   │ 装备槽位 │
    │(随身)   │   │(据点)   │   │(穿戴中)  │
    │容量有限  │   │容量较大  │   │固定槽位  │
    │随时存取  │   │据点存取  │   │属性加成  │
    └─────────┘   └─────────┘   └────┬────┘
                                     │
                              ┌──────▼──────┐
                              │StatModifier │  ←── 属性加成复用现有系统
                              │Manager      │
                              └─────────────┘
```

核心设计原则：
- **物品模板与实例分离**：ItemSO 定义「什么是火焰剑」，ItemInstance 定义「这把火焰剑在谁的包里」
- **容器抽象**：背包、仓库、装备槽位都是「能放物品的容器」，统一操作接口
- **属性加成走修饰器**：装备提供的属性变化全部通过现有 StatModifierManager 管道，零侵入
- **事件驱动**：物品流转全部走 EventBus，UI 只管订阅刷新

## 二、物品数据结构

### 2.1 ItemSO — 物品模板（ScriptableObject）

```
ItemSO : ScriptableObject
├── string itemName           // 物品名称
├── string description        // 描述文本
├── Sprite icon               // 物品图标
├── ItemType itemType         // 枚举：消耗品/装备/材料/任务物品/杂项
├── ItemRarity rarity         // 稀有度：普通/稀有/史诗/传说
├── int maxStack              // 最大堆叠数（0=不可堆叠）
├── int sellPrice             // 出售价格（0=不可出售）
├── bool isDiscardable        // 是否可丢弃
│
├── [ItemType == Consumable]
│   ├── ConsumableEffect[] effects     // 使用效果列表
│   └── float cooldownGroup            // 同类冷却组（0=无冷却）
│
├── [ItemType == Equipment]
│   ├── EquipmentSlot slot             // 装备槽位类型
│   ├── EquipmentStatBonus[] bonuses   // 装备属性加成
│   ├── WeaponType? weaponType         // 武器类型（武器槽位时必需）
│   └── WeaponSkillData weaponSkill    // 武器技能引用（武器槽位时）
│
└── [ItemType == Material]
    └── string materialCategory        // 材料分类（合成/强化/任务）
```

### 2.2 ItemInstance — 物品运行时实例

```
class ItemInstance              // 普通 C# class，非 MonoBehaviour
├── string instanceId          // 全局唯一 ID（GUID）
├── ItemSO template            // 指向模板 SO
├── int count                  // 当前堆叠数量
├── int slotIndex              // 所在容器槽位（-1=无容器）
│
└── [额外持久化字段 - 仅运行时，不存 SO]
    └── Dictionary<string, object> customData   // 预留扩展
```

### 2.3 物品类型枚举

| 类型 | 说明 | 典型行为 |
|------|------|---------|
| `Consumable` | 消耗品 | 使用后减少数量，触发效果 |
| `Equipment` | 装备 | 可穿戴到装备槽位，提供属性加成 |
| `Material` | 材料 | 用于合成/强化/任务提交 |
| `QuestItem` | 任务物品 | 不可丢弃/不可出售，任务专用 |
| `Misc` | 杂项 | 无特殊行为，仅展示 |

### 2.4 稀有度枚举

| 稀有度 | 颜色 | 说明 |
|--------|------|------|
| `Common` | #999999 灰 | 普通掉落 |
| `Rare` | #4488FF 蓝 | 稀有掉落 |
| `Epic` | #AA66FF 紫 | 史诗级 |
| `Legendary` | #FFD700 金 | 传说级 |

**编辑器配置**：ItemSO 在 Project 窗口右键 → `Create → Game → ItemData` 创建，Inspector 调整所有字段。稀有度颜色由 UI 代码常量表映射。

## 三、背包系统

### 3.1 核心规则

| 项目 | 规格 |
|------|------|
| 初始容量 | 20 格 |
| 容量扩展 | 通过游戏内升级/道具扩容，上限暂定 60 |
| 堆叠规则 | 同 ItemSO 且 maxStack > 0 自动堆叠；不可堆叠物品每格 1 个 |
| 操作限制 | 战斗中可打开查看，但禁止使用/丢弃/移动（与 PassiveEquipManager 一致） |

### 3.2 运行时数据结构

```
Inventory : MonoBehaviour (挂 Player)
├── ItemInstance[] slots                  // 槽位数组，null = 空槽
├── int capacity                          // 当前容量
├── Dictionary<string, int> quickSlot     // 快捷栏 {热键 → 槽位索引}，可选
│
├── public bool AddItem(ItemSO template, int count)
├── public bool RemoveItem(string instanceId, int count)
├── public bool UseItem(int slotIndex)
├── public bool DiscardItem(int slotIndex, int count)
├── public bool MoveItem(int fromSlot, int toSlot)         // 槽位交换
├── public bool SplitStack(int slotIndex, int amount)      // 堆叠拆分
├── public List<ItemInstance> GetFiltered(ItemType? type, ItemRarity? rarity)  // 筛选
├── public void SortBy(SortMode mode)                      // 排序
│
└── 事件触发:
    ├── ItemAddedEvent
    ├── ItemRemovedEvent
    └── InventoryChangedEvent
```

### 3.3 物品获取/丢弃/使用流程

```
[获取]
  怪物掉落 / 宝箱 / 任务奖励 / 购买
        │
  调用 Inventory.AddItem(template, count)
        │
  ├── 检查容量：满则拒绝，触发 InventoryFullEvent
  ├── 查找可堆叠槽位（同 ItemSO + count < maxStack）
  │   ├── 找到 → 叠加数量
  │   └── 未找到 → 占用新空槽
  └── 触发 ItemAddedEvent → UI 刷新

[丢弃]
  玩家选择物品 → 确认弹窗 → Inventory.DiscardItem(id, count)
  ├── 任务物品（QuestItem）禁止丢弃
  ├── 数量减少 → count<=0 时清空槽位
  └── 触发 ItemRemovedEvent → UI 刷新

[使用]
  玩家选择消耗品 → Inventory.UseItem(slotIndex)
  ├── IsConsumable 检查
  ├── 使用效果执行（回血/回蓝/临时Buff等）
  ├── 数量-1 → count<=0 时清空
  └── 触发 ItemUsedEvent → UI 刷新
```

### 3.4 排序与筛选

**排序模式（SortMode 枚举）**：

| 模式 | 规则 |
|------|------|
| `TypeThenRarity` | 先按类型分组（装备>消耗品>材料>任务>杂项），组内按稀有度降序 |
| `RarityThenType` | 先按稀有度降序，同稀有度按类型分组 |
| `Name` | 按物品名首字母排序 |
| `Count` | 按堆叠数量降序 |

**筛选**：UI 提供类型标签页 + 稀有度复选框，调用 `GetFiltered()` 返回结果列表。

### 3.5 与现有系统的对接点

| 现有系统 | 对接方式 |
|---------|---------|
| **SaveSystem** | 新增 `CollectInventory()` / `RestoreInventory()`，序列化 slots 数组 |
| **PanelManager** | 注册 InventoryPanel 为 FullScreen 面板，P 键为技能面板保留，背包建议 B 键 |
| **StatModifierManager** | 消耗品使用时可能添加临时 Modifier（如「攻击力+20% 持续 30s」），source 前缀 `Item_` + instanceId |

**程序实现**：Inventory 组件、ItemInstance 类、相关事件定义、SaveSystem 扩展

## 四、仓库系统

### 4.1 核心规则

| 项目 | 规格 |
|------|------|
| 容量 | 固定 100 格（不可扩展） |
| 访问条件 | 到达据点/安全区域时可用，战斗中不可打开 |
| 存取操作 | 免费，不消耗任何资源 |
| 堆叠规则 | 与背包一致 |
| 排序筛选 | 复用背包逻辑 |

### 4.2 数据结构

```
Warehouse : MonoBehaviour (挂独立 GameObject 或 Player)
├── ItemInstance[] slots              // 100格槽位
│
├── public bool Deposit(int inventorySlot, int count)   // 从背包存入
├── public bool Withdraw(int warehouseSlot, int count)  // 从仓库取出
├── public List<ItemInstance> GetFiltered(...)          // 复用筛选逻辑
├── public void SortBy(SortMode mode)                   // 复用排序逻辑
│
└── 事件触发:
    ├── WarehouseDepositEvent
    └── WarehouseWithdrawEvent
```

### 4.3 存取交互流程

```
[存入] 背包界面选中物品 → 「存入仓库」按钮
  前置条件：仓库有空槽位（含堆叠空位）
  ├── Warehouse.Deposit(inventorySlot, count)
  ├── 仓库添加物品（堆叠优先）
  ├── 背包减少/清空对应槽位
  └── 双发事件：ItemRemovedEvent + WarehouseDepositEvent

[取出] 仓库界面选中物品 → 「取出」按钮
  前置条件：背包有空位（含堆叠空位）
  ├── Warehouse.Withdraw(warehouseSlot, count)
  ├── 背包添加物品
  ├── 仓库减少/清空对应槽位
  └── 双发事件：ItemAddedEvent + WarehouseWithdrawEvent
```

### 4.4 数据持久化

仓库数据作为独立存档段，与背包分开序列化：

```
SaveData 新增字段:
├── ItemSaveData[] inventorySlots
└── ItemSaveData[] warehouseSlots

ItemSaveData:
├── string templateId          // ItemSO 的 name 字段作为唯一标识
├── string instanceId          // 实例 GUID
├── int count
└── int slotIndex
```

### 4.5 与现有系统的对接点

| 现有系统 | 对接方式 |
|---------|---------|
| **SaveSystem** | 新增 `CollectWarehouse()` / `RestoreWarehouse()` |
| **PanelManager** | 仓库面板注册为 FullScreen 面板 |
| **事件** | 仓库操作不影响战斗系统，仅在物品流转时发事件供 UI 刷新 |

**程序实现**：Warehouse 组件、ItemSaveData、SaveSystem 扩展、UI 面板（数据接口暴露即可）

## 五、人物装备系统

### 5.1 装备槽位定义

| 槽位 | 枚举 ID | 现有系统关联 |
|------|---------|-------------|
| 武器 | `Weapon` | 装备武器 → 触发 WeaponSkillLink（激活武器技能） |
| 头部 | `Head` | 纯属性加成 |
| 身体 | `Body` | 纯属性加成 |
| 腿部 | `Legs` | 纯属性加成 |
| 饰品1 | `Accessory1` | 纯属性加成 |
| 饰品2 | `Accessory2` | 纯属性加成 |

共 6 个槽位，武器槽位与现有 WeaponSkillLink 深度关联。

### 5.2 装备数据结构（ItemSO 的 Equipment 子段）

```
EquipmentStatBonus (定义在 ItemSO 内):
├── string statId              // 使用 StatId 常量
├── float value                // 加成值
├── ModifierType type          // Percent 或 Flat
```

示例 — 火焰剑 ItemSO：
```
slot: Weapon
weaponType: Sword
weaponSkill: Skill_Weapon_Sword.asset
bonuses:
  [{statId: "damageMultiplier", value: 0.15, type: Percent},
   {statId: "attackSpeedMultiplier", value: 0.10, type: Percent}]
```

### 5.3 装备管理器

```
EquipmentManager : MonoBehaviour (挂 Player)
├── ItemInstance[] equippedSlots        // [6] 6个槽位，null=空
│
├── public bool Equip(string instanceId, int fromInventorySlot)
│   前置条件：物品 ItemType == Equipment
│   ├── 目标槽位非空 → 先 Unequip 旧装备（放回背包）
│   ├── 从背包移除物品
│   ├── 填入装备槽位
│   ├── 调用 AddEquipmentModifiers(ItemInstance)
│   │   └── 将 ItemSO.bonuses 转为 Modifier 对象，source="Equip_" + instanceId
│   │       送入 StatModifierManager.AddModifier()
│   ├── 如果是 Weapon 槽位 → 触发 WeaponEquippedEvent
│   └── 触发 EquipmentChangedEvent
│
├── public bool Unequip(EquipmentSlot slot)
│   前置条件：背包有空位
│   ├── 调用 RemoveEquipmentModifiers(slot)
│   │   └── StatModifierManager.RemoveModifier("Equip_" + instanceId)
│   ├── 如果是 Weapon 槽位 → 触发 WeaponUnequippedEvent
│   ├── 装备移回背包
│   ├── 清空槽位
│   └── 触发 EquipmentChangedEvent
│
├── public ItemInstance GetEquipped(EquipmentSlot slot)  // UI查询
│
└── 事件:
    └── EquipmentChangedEvent(slot, action)  // "equip" / "unequip"
```

### 5.4 与现有系统的整合关系

```
装备系统 ←→ 现有系统的 4 层耦合

1. 武器槽位 ⇄ WeaponSkillLink
   Equip(slot=Weapon) → WeaponEquippedEvent → WeaponSkillLink 激活武器技能
   Unequip(slot=Weapon) → WeaponUnequippedEvent → WeaponSkillLink 移除武器技能
   ※ 完全兼容，无需修改 WeaponSkillLink 代码

2. 属性加成 ⇄ StatModifierManager
   装备的每个 EquipmentStatBonus → Modifier → AddModifier()
   source 使用 "Equip_" + instanceId，同 source 覆盖（换装自动替换）
   ※ 完全复用现有管道，不需要修改 StatModifierManager 代码

3. 战斗锁定 ⇄ PassiveEquipManager 的 inCombat 约束
   EquipmentManager 同样检查 inCombat 状态
   通过 EventBus 订阅战斗状态事件或直接查询 PassiveEquipManager.InCombat

4. 存档 ⇄ SaveSystem
   新增 CollectEquipment() / RestoreEquipment()
   保存 6 个槽位的装备实例 ID
```

### 5.5 装备系统 vs 已有被动系统 — 边界澄清

| 维度 | 装备系统 (Equipment) | 被动系统 (PassiveEquip) |
|------|---------------------|------------------------|
| 数据载体 | ItemSO → ItemInstance（背包中流转） | PassiveSkillData SO（25个，选中即生效） |
| 获取方式 | 掉落/购买/任务奖励 | 等级解锁后点击选择 |
| 数量限制 | 每槽位 1 件，共 6 件 | 每层 3 线，共 5 层 |
| 属性管道 | StatModifierManager（source="Equip_xxx"） | StatModifierManager（source="Passive_Lx_Lx"） |
| 战斗中操作 | 锁定 | 锁定 |
| UI 面板 | 角色装备面板（独立） | 被动网格面板（已有 PassiveUI） |

**两者互不冲突，平行运作，通过 StatModifierManager 的属性叠加公式自然合并**。

### 5.6 新属性 ID 需求（如装备系统引入新加成维度）

当前 StatId 已定义：MoveSpeed, MaxHealth, DamageMultiplier, DamageReduction, AttackSpeedMultiplier, DodgeChance, ControlReduction, ManaCostMultiplier, MaxMana, ManaRegen, CooldownMultiplier, StunReduction。

装备系统可能新增的属性 ID：

| 新增 StatId | 类型 | 说明 |
|------------|------|------|
| `CriticalChance` | Percent [0~1] | 暴击率 |
| `CriticalDamage` | Percent | 暴击伤害倍率 |
| `ExpMultiplier` | Percent | 经验获取倍率 |
| `ItemDropRate` | Percent | 物品掉率加成 |

**编辑器配置**：每新增一个 StatId，在 `StatModifierManager.ClampConfig` 中添加钳制范围即可。

**程序实现**：EquipmentManager 组件、EquipmentChangedEvent、SaveSystem 扩展、StatId 常量扩展

## 六、数据持久化方案

### 6.1 整体方案建议

| 选项 | 推荐度 | 说明 |
|------|--------|------|
| **JSON + PlayerPrefs**（当前 SaveSystem 方式） | ★★★ | 与现有架构一致，数据量小时最简 |
| JSON + File | ★★★★ | 扩展到文件存储，支持多存档槽位 |
| BinaryFormatter | ★ | 架构不兼容，不推荐 |
| SQLite | ★★ | 物品量大时考虑，目前过度 |

**建议**：短期沿用 PlayerPrefs JSON 方案（与 SaveSystem 一致），中期迁移到文件系统 JSON（支持多存档槽位）。

### 6.2 扩展后的 SaveData 结构

```
SaveData:
├── int skillPoints                    // 已有
├── SlotSaveData[] slotData            // 已有（4技能槽）
├── PassiveLayerSave[] passiveLayers   // 已有（5层被动）
├── WeaponSaveData weapon              // 已有
│
├── [新增] ItemSaveData[] inventorySlots       // 背包
├── [新增] ItemSaveData[] warehouseSlots       // 仓库
├── [新增] int inventoryCapacity               // 背包当前容量
└── [新增] EquipSlotSaveData[] equipmentSlots  // 装备（6槽）

ItemSaveData:
├── string templateId       // ItemSO.skillName 或专用 templateId
├── string instanceId       // GUID
├── int count
└── int slotIndex

EquipSlotSaveData:
├── int slotEnum            // EquipmentSlot 枚举值
└── string instanceId       // 装备的物品实例 ID（null/""=空）
```

### 6.3 ItemSO 的存档引用策略

**问题**：JSON 序列化无法保存 ScriptableObject 引用（GUID 不可靠跨设备）。

**方案**：给 ItemSO 添加 `templateId` 字段（string），存档时保存 templateId，读档时通过 templateId 查找 ItemSO：

```
// 查找策略（Load 时）
1. Resources.LoadAll<ItemSO>("Items/")  → Dictionary<string, ItemSO> 索引
2. 通过 templateId 查找对应 SO 引用
```

**编辑器配置**：创建 ItemSO 时确保 templateId 唯一。可在 Editor 脚本中加重复检查。
**程序实现**：SaveSystem 扩展 + ItemDatabase 查找类

## 七、UI 交互概览

### 7.1 面板清单及关系

```
PanelManager 注册的面板（扩展后）:

已有: SkillTreePanel (P键)  |  CraftPanel  |  PassivePanel
新增: InventoryPanel (B键)  |  WarehousePanel  |  EquipmentPanel (C键)
```

面板层级关系：

```
┌─────────────────────────────────────┐
│ Canvas                              │
├─────────────────────────────────────┤
│ ┌─ InventoryPanel (FullScreen)      │
│ │  ├── SlotGrid (ScrollView)        │
│ │  ├── SortButtons                  │
│ │  ├── FilterTabs (消耗品|装备|...)  │
│ │  ├── ItemDetailPanel (选中时)      │
│ │  └── ActionButtons (使用|丢弃|...) │
│ │                                   │
│ └─ EquipmentPanel (FullScreen)      │
│    ├── CharacterPreview             │
│    ├── EquipmentSlots (6槽位)       │
│    │   [武器] [头部] [身体]         │
│    │   [腿部] [饰品1] [饰品2]       │
│    ├── StatSummary (属性汇总)       │
│    └── InventorySidePanel (迷你背包) │← 装备时勾选背包物品
│                                     │
│ WarehousePanel (FullScreen)         │
│    ├── WarehouseGrid                │
│    ├── InventorySidePanel           │← 存取时双栏显示
│    └── ActionButtons (存入|取出)     │
└─────────────────────────────────────┘
```

### 7.2 面板切换与数据流

```
打开背包 (B键)
  → PanelManager.OpenPanel(InventoryPanel)
  → InventoryPanel.OnEnable 调用 Inventory.GetAllItems() 刷新 UI
  → 关闭(ESC) → PanelManager.CloseTopPanel()

打开装备 (C键)
  → PanelManager.OpenPanel(EquipmentPanel)
  → 显示 6 槽位当前装备 + 背包物品列表
  → 玩家点击背包物品装备 → EquipmentManager.Equip()
  → 属性汇总区域读取 StatModifierManager.GetActiveModifiers()

打开仓库 (据点内)
  → PanelManager.OpenPanel(WarehousePanel)
  → 双栏：左背包 / 右仓库
  → 存入/取出操作 → 事件驱动双栏刷新
```

### 7.3 拖拽交互建议

| 操作 | 交互方式 | 适用场景 |
|------|---------|---------|
| 背包内移动物品 | 拖拽到目标槽位 | 整理背包 |
| 装备物品 | 双击背包物品 OR 拖到装备槽位 | 快速换装 |
| 卸下装备 | 双击装备槽位 OR 拖到背包区域 | 卸装 |
| 存取仓库 | 拖拽跨越面板边界（背包⇄仓库面板） | 批量存取 |
| 丢弃物品 | 拖出面板边界 OR 右键菜单 | 清背包 |

**注意**：拖拽交互是 UI 层的糖，核心数据操作仍通过 Manager 的方法（Equip/Unequip/Deposit/Withdraw）执行，UI 只负责「把操作翻译为方法调用 + 刷新显示」。

### 7.4 信息提示

| 提示类型 | 触发条件 | 显示内容 |
|---------|---------|---------|
| 物品悬停 Tooltip | 鼠标悬停物品图标 | 名称、稀有度、描述、堆叠数、属性加成预览 |
| 属性对比 Tooltip | 悬停可装备物品（已穿戴同槽位时） | 当前装备 vs 目标装备的属性差异（绿色增益/红色减益） |
| 容量警告 | 背包满时获取物品 | 「背包已满」浮窗提示 + 物品掉落地面 |

**程序实现**（UI部分）：InventoryPanel、EquipmentPanel、WarehousePanel 的 UI 脚本（含槽位渲染、拖拽、Tooltip）、PanelManager 注册项扩展

## 十、关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 物品数据模型 | SO 模板 + 运行时实例分离 | 兼容现有 SO 资产体系，存档只存 templateId + 运行时状态 |
| 装备属性管道 | 走 StatModifierManager | 零侵入现有系统，自动参与属性汇总和 UI 刷新 |
| 存档方案 | JSON + PlayerPrefs → 未来迁移文件 | 与 SaveSystem 保持一致，中期扩展多存档槽位 |
| 仓库是否分页 | 不需要，100 格 ScrollView 足够 | 2D 游戏物品种类有限，100 格+筛选已够用 |
| 是否多仓库 | 不需要，单一 100 格仓库 | 避免复杂度，未来如需可扩展（Warehouse 数组化） |
| 武器装备与 WeaponSkillLink 的关系 | 事件驱动，不改 WeaponSkillLink | WeaponSkillLink 已有完善的装备/卸下事件监听，装备系统只需触发事件即可 |
| 拖拽交互 | 后期打磨项（P5） | 先保证数据正确，再优化交互体验 |
| 战斗中背包操作 | 允许查看、禁止修改 | 与 PassiveEquipManager 的 inCombat 锁定策略一致 |
