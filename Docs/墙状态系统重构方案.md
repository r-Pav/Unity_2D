# 墙状态系统重构方案

## 一、现状诊断

### 1.1 文件分布（8文件 / 6类 / 3目录）

```
Assets/Scripts/
├── PlayerCharacterBase.cs          ← 墙检测 + 墙参数 + CheckWallTop/CanVault
├── Player/
│   ├── PlayerController.cs          ← 墙入口检测 + 墙跳力参数 + FreezeTimer + 墙出口检测
│   └── States/
│       ├── WallSlideStateBase.cs    ← 下滑基类（含 PlayerController 强转）
│       ├── WallSlideState.cs        ← 普通下滑（24行）
│       ├── WallFastSlideState.cs    ← 加速下滑（24行）
│       ├── WallClimbState.cs        ← 上爬 + 翻顶过渡
│       ├── WallJumpState.cs         ← 三方向墙跳
│       └── WallVaultState.cs        ← 翻顶瞬移
```

### 1.2 六大问题

#### P0: 基类反向依赖子类（6处 cast）

所有状态类均通过 `player as PlayerController` 强转访问：
- WallSlideStateBase → 获取 `pc.WallClimbState`/`pc.WallJumpState`
- WallSlideState → 获取 `pc.WallFastSlideState`
- WallFastSlideState → 获取 `pc.WallSlideState`
- WallClimbState → 获取 `pc.WallSlideState`/`pc.WallVaultState`
- WallJumpState → 获取 `pc.WallJump*Force` + `pc.FreezeTimer` + `pc.ClearWallContact()`
- WallVaultState → 获取 `pc.FreezeTimer`

类型安全的接口抽象被绕过，多态完全失效。

#### P0: 翻顶逻辑三处散落

| 位置 | 职责 |
|------|------|
| PlayerCharacterBase.CheckWallTop() | 头顶射线检测 |
| PlayerCharacterBase.CanVault() | 目标空间无障碍检测 |
| PlayerController.CheckShortWallVault() | 矮墙入口（脚命中+头未命中→直接Vault） |
| WallClimbState.TryTransitionToVault() | 爬墙中检测翻顶条件 |

翻顶的"何时检测 / 如何检测 / 如何执行"被拆散在三个类中，调试时需要在多处打断点。

#### P1: FastSlide 过度拆分

WallFastSlideState 与 WallSlideState 的唯一差异：

| | WallSlideState | WallFastSlideState |
|---|---|---|
| MaxSpeed | `-wallSlideSpeed` | `-wallSlideSpeed * multiplier` |
| OnSlideInput | S键→切FastSlide | 松S→切回Slide |

差异仅为一个倍率参数和一个布尔判断。24行代码独立成类，徒增复杂度。

#### P1: 墙检测代码重复

- `PlayerCharacterBase.CheckWall()` 写死脚/头双射线
- `PlayerController.RaycastWallDual()` 再次写脚/头双射线（用基类的 GetWallCheckFootOrigin/HeadOrigin）

基类已提供原点方法，但 PlayerController 仍重写一次射线逻辑用于矮墙检测——同一份射线源+方向+距离，在不同方法中各自 Raycast。

#### P2: 退出检测逻辑三份相同实现

```csharp
// WallSlideStateBase.CheckExitConditions()
if (!player.IsTouchingWall || player.IsGrounded) { stateMachine.ChangeState(null); return true; }

// WallClimbState.CheckExit()
if (!player.IsTouchingWall || player.IsGrounded) { stateMachine.ChangeState(null); return true; }

// PlayerController.CheckWallExit()
if (WallStateMachine.CurrentState != null && (!isTouchingWall || grounded)) { WallStateMachine.ChangeState(null); }
```

PlayerController 的 CheckWallExit 是防御性的全局退出检查，与各状态类内部检查形成双重检测——状态类内部退出后，CheckWallExit 再次检查。职责边界模糊。

#### P2: 墙参数分散两文件

| 文件 | 参数 |
|------|------|
| PlayerCharacterBase | wallCheckFootHeight, wallCheckHeadHeight, wallCheckDistance, wallSlideSpeed, wallFastSlideMultiplier, wallClimbSpeed, wallClimbHoldTime, wallClimbCheckOffset, vaultUpOffset, vaultForwardOffset, enableWallDetection, wallLayer |
| PlayerController | wallJumpAwayForceX/Y, wallJumpPushForceX/Y, wallJumpUpForce |

策划调参时需要打开两个 Inspector 面板。

## 二、重构目标

重构为4个状态类：**下滑 / 爬墙 / 登墙跳 / 翻顶**，消除上述全部 P0~P2 问题。

```

├── PlayerController.cs              ← 主控制器（精简，不再持有墙参数和墙检测）
├── WallConfig.cs                     ← [NEW] 所有墙参数的 SO 聚合
```

**删除文件：** WallSlideStateBase.cs、WallFastSlideState.cs

**修改文件：** PlayerCharacterBase.cs（移除墙相关所有内容）

## 四、WallConfig（ScriptableObject）

所有墙参数聚合到一个 SO，一处调参。

```
WallConfig
├── 检测
│   ├── footHeight: float
│   ├── headHeight: float
│   ├── distance: float
│   ├── wallLayer: LayerMask
│   └── enableDetection: bool
├── 下滑
│   ├── slideSpeed: float
│   └── fastSlideMultiplier: float
├── 爬墙
│   ├── climbSpeed: float
│   ├── climbHoldTime: float
│   └── checkOffset: float
├── 翻顶
│   ├── vaultUpOffset: float
│   └── vaultForwardOffset: float
└── 墙跳
    ├── awayForceX: float
    ├── awayForceY: float
    ├── pushForceX: float
    ├── pushForceY: float
    └── upForce: float
```

PlayerController 挂载 `[SerializeField] WallConfig wallConfig`，注入到 WallSystem。

## 五、WallSystem（统一管理墙检测 + 状态机）

取代 PlayerCharacterBase 中所有墙逻辑 + PlayerController 中的入口/出口检测。

```
职责：
  - 持有 WallStateMachine（内部静态状态机实例）
  - 持有4个状态实例的引用（消除 cast）
  - public FreezeTimer（消除 PlayerController 上的分散状态）
  - public IsTouchingWall / WallDirection（消除 PlayerCharacterBase 上的分散状态）
  - CheckWall() — 唯一墙检测入口
  - CheckWallTop() / CanVault() — 翻顶检测（从 PlayerCharacterBase 迁入）
  - DetectEntry() — 合并原 DetectWallEntry + CheckShortWallVault + TryEnterWallState
  - CheckExit() — 全局退出检查
```

### WallSystem 公开接口

```
public bool IsTouchingWall;
public int WallDirection;
public float FreezeTimer;
public bool IsWallActive => StateMachine.CurrentState != null;

public void UpdateCooldowns();           // FreezeTimer 递减
public void DetectEntry();               // 入口检测（含矮墙翻顶）
public void UpdateState();               // 驱动 StateMachine.Update()
public void CheckExit();                 // 全局退出检查
public void ClearWallContact();

// 翻顶检测（供状态类调用）
public bool CheckWallTop();
public bool CanVault();

// 获取其他状态的引用（消除 cast）
public T GetState<T>() where T : IState;
```

### 入口检测统一流程

```
DetectEntry():
  if StateMachine.CurrentState != null → return
  if player.IsGrounded → return
  if FreezeTimer > 0 → return

  // 1. 矮墙翻顶检测（脚命中+头未命中）
  if TryShortWallVault() → return

  // 2. 普通贴墙入口
  if IsTouchingWall:
      Space键 → 进 WallJumpState
      否则   → 进 WallSlideState
```

## 六、状态转换图

```
                    ┌──────────────────────────────────┐
                    │         Common Exit               │
                    │  !IsTouchingWall || IsGrounded    │
                    │  → None (所有状态统一退出)         │
                    └──────────────────────────────────┘
                                    ↑
    ┌───────┐              ┌───────┴───────┐
    │ Slide │──[W计时]──→  │   Climb       │
    │       │←──[松W]──────│               │
    │       │              │  [头顶无墙     │
    │       │──[Space]──→  │   +CanVault]  │
    │       │              │       ↓       │
    │       │              │    Vault      │
    │  [S键=快 / 松S=慢]   │               │
    └───┬───┘              └───────────────┘
        │
        │ [Space]
        ↓
    ┌───────┐
    │ Jump  │──[OnEnter执行完]──→ None
    └───────┘

    None ──[矮墙检测: 脚命中+头未命中]──→ Vault → None
    None ──[贴墙+Space]──→ Jump → None
    None ──[贴墙]──→ Slide
```

**优先级规则：**
1. Common Exit（不贴墙/落地）→ 最高优先，先于所有输入处理
2. 矮墙翻顶 → 先于普通贴墙入口检查
3. 状态内的输入检查（Space → Jump, W → Climb, S → 快滑）→ 在物理更新之前

## 七、4个重构后的状态类

### 7.1 WallSlideState（合并 Slide + FastSlide）

```
字段:
  float speedMultiplier = 1.0f   // 1.0=慢滑, wallFastSlideMultiplier=快滑

OnUpdate:
  1. CommonExit → None
  2. W按住计时 → Climb
  3. Space → Jump
  4. S键 → speedMultiplier = fastSlideMultiplier; 松S → speedMultiplier = 1.0
  5. ApplyPhysics: clampedY = Max(speed, -slideSpeed * speedMultiplier)
                   朝墙方向水平=0
```

不再有 OnSlideInput 虚方法回调，逻辑内联在 OnUpdate 中。

### 7.2 WallClimbState

```
OnUpdate:
  1. CommonExit → None
  2. 松W → Slide
  3. ApplyPhysics: Y = climbSpeed, 朝墙水平=0
  4. CheckWallTop + CanVault → Vault
```

不需要 cast，通过 WallSystem.GetState<WallSlideState>() 获取引用。

### 7.3 WallJumpState

```
OnEnter:
  根据 inputH 三方向分支，设置 velocity + AddForce
  wallSystem.FreezeTimer = 0.1f
  wallSystem.ClearWallContact()
  stateMachine.ChangeState(null)

OnUpdate: (空)
```

墙跳参数从 WallConfig 读取（注入到 WallSystem 的引用）。

### 7.4 WallVaultState

```
OnEnter:
  rb.position = 目标位置
  wallSystem.FreezeTimer = 0.15f
  stateMachine.ChangeState(null)

OnUpdate: (空)
```

## 八、PlayerController 精简后的 OnUpdate

```
protected override void OnUpdate()
{
    if (!InputEnabled) return;

    wallSystem.UpdateCooldowns();           // FreezeTimer 递减

    if (dash?.OnPlayerUpdate(this) == true) return;

    wallSystem.DetectEntry();               // 入口检测（含矮墙翻顶）
    wallSystem.UpdateState();               // 驱动当前状态 OnUpdate
    wallSystem.CheckExit();                 // 全局退出检查

    jump?.OnPlayerUpdate(this);
    health?.OnPlayerUpdate(this);

    UpdateSubModules();
}
```

PlayerController 不再持有：
- WallStateMachine + 5个状态实例引用
- FreezeTimer
- 墙跳力参数
- DetectWallEntry / CheckWallExit / CheckShortWallVault / TryEnterWallState / RaycastWallDual
- vaultTriggered

全部移入 WallSystem。

### FixedUpdate 精简

```
protected override void OnFixedUpdate()
{
    if (!InputEnabled) return;
    if (dash != null && dash.IsDashing) return;
    if (wallSystem.FreezeTimer > 0f) return;

    float h = Input.GetAxisRaw("Horizontal");

    if (wallSystem.IsTouchingWall && Mathf.Sign(h) == wallSystem.WallDirection)
        h = 0f;

    if (wallSystem.IsWallActive) return;    // 墙状态活跃 → 跳过普通移动

    if (Mathf.Abs(h) > 0.1f) { Move(h); UpdateFacing(h); }
    else                      { Move(0f); }
}
```

## 十一、状态类依赖消除方案

原状态类通过 `player as PlayerController` 获取三种资源：

| 资源 | 旧方式 | 新方式 |
|------|--------|--------|
| 其他状态实例 | `pc.WallSlideState` | `wallSystem.GetState<WallSlideState>()` |
| 墙跳力参数 | `pc.WallJumpAwayForceX` | `wallSystem.Config.awayForceX` |
| FreezeTimer | `pc.FreezeTimer` | `wallSystem.FreezeTimer` |
| ClearWallContact | `pc.ClearWallContact()` | `wallSystem.ClearWallContact()` |

所有状态类构造函数从 `(PlayerCharacterBase, StateMachine)` 改为 `(PlayerCharacterBase, WallSystem)`。

## 十三、风险点

1. **矮墙翻顶时序**：原 CheckShortWallVault 在 `isTouchingWall == false` 时工作（依赖 Update() 中基类 CheckWall 的时序）。移入 WallSystem 后需确保 DetectEntry 中 IsTouchingWall 状态已更新。
2. **FreezeTimer 移动**：原在 PlayerController，移入 WallSystem。如果有非墙逻辑依赖 FreezeTimer（当前无），需确认。
3. **Gizmos**：PlayerCharacterBase 的墙 Gizmos 需迁移到 WallSystem，或以 Editor-only 方式保留引用。
4. **序列化数据丢失**：PlayerCharacterBase 和 PlayerController 上现有的 `[SerializeField]` 墙参数在字段移除后会丢失 Inspector 配置值。需要手动迁移到 WallConfig SO，或在重构前先导出配置值。
