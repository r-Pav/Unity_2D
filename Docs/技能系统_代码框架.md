## 二、类命名规范

### 2.1 后缀规则表

所有技能系统类的后缀必须遵循下表，不混用：

| 后缀 | 用途 | 示例 |
|------|------|------|
| `Manager` | 管理类（MonoBehaviour，挂载在 Player 上，管理生命周期和数据） | SkillManager, StatModifierManager, PassiveEquipManager |
| `System` | 系统逻辑类（无状态逻辑处理器，可挂 Player 或作为 Manager 的子模块） | BranchUpgradeSystem, CombinationCraftSystem |
| `Link` | 联动桥接组件（监听事件并转发数据到其他系统） | WeaponSkillLink |
| `Data` | ScriptableObject 配置数据 | SkillData, BarrierSkillData, ActiveSkillData |
| `Config` | 配置类 SO 或可序列化结构 | SynergyConfig |
| `Modifier` | 修饰器数据模型（struct 或 class，纯数据不包含逻辑） | Modifier（StatModifier 别名） |
| 无后缀 | 具体功能组件（MonoBehaviour，实现接口） | BarrierSkill, ObstacleBall |

### 2.2 ScriptableObject 命名规则

| 规则 | 示例 |
|------|------|
| 文件名前缀 `Skill_` + 类型提示 | `Skill_FireBall`, `Skill_Barrier_Reflect` |
| CreateAssetMenu menuName 遵循分层 | `Game/SkillData`（基类）, `Game/SkillData/Barrier`（子类）, `Game/SynergyConfig`（独立配置） |
| 文件名与 skillName 无关 | SO 文件名 = 资产标识，skillName = 运行时显示名称 |

### 2.3 接口命名规则

| 规则 | 示例 |
|------|------|
| 接口前缀 `I` | ISkill |
| 接口文件名与接口名一致 | ISkill.cs |
| 接口定义在 Skills/ 根目录 | 不与具体实现混在同一文件 |

### 2.4 事件结构体命名规则

| 规则 | 示例 |
|------|------|
| 后缀 `Event` | SkillActivatedEvent |
| readonly struct | 不可变值类型 |
| 所有字段 public readonly | 构造时赋值 |
| 全部在 Events.cs 中定义 | 不分散到多个文件 |

## 三、类层次架构

### 3.1 StatModifierManager（P1 — 属性修饰器管理器）

**定位**：统管 Player（和未来 Enemy）所有属性的修饰器管线。

**调用关系**：
```
PassiveEquipManager ──AddModifier/RemoveModifier──→ StatModifierManager
WeaponSkillLink     ──AddModifier/RemoveModifier──→ StatModifierManager
(Buff系统/P6)       ──AddModifier/RemoveModifier──→ StatModifierManager
                            │
                            ▼
                    GetFinalValue(statId)
                            │
                    ┌───────┴───────┐
                    ▼               ▼
              CharacterBase    PlayerHealth
              (moveSpeed)      (maxHealth)
```

**关键接口**：
```
public void AddModifier(Modifier mod)
public void RemoveModifier(string source)
public void RemoveAllModifiers()
public float GetFinalValue(float baseValue, string statId)
public List<Modifier> GetActiveModifiers(string statId)  // 调试/UI
```

**触发事件**：
- 任何 Add/Remove 后 → `EventBus.Trigger(new StatModifiersChangedEvent(affectedStatIds))`

### 3.2 PassiveEquipManager（P2 — 被动装备管理器）

**定位**：管理 5 层被动槽位（每层 5 选 3），装备/卸下时通过 StatModifierManager 生效。

**调用关系**：
```
PassiveEquipManager
    ├── EquipPassive(layer, lineId) → 调用 StatModifierManager.AddModifier()
    ├── UnequipPassive(layer, lineId) → 调用 StatModifierManager.RemoveModifier()
    ├── GetLayoutData() → 暴露给 UI (5×3 槽位状态)
    └── 触发 PassiveSlotsChangedEvent → UI 刷新
```

**数据载体**：`PassiveSkillData`（SO，每节点一条线的数据，含 effects 数组）。

**约束**：
- 仅非战斗状态可操作
- 同层 5 选 3，不可重复同一条线
- 多层选同线 → 修饰器在 StatModifierManager 层叠加

### 3.3 BranchUpgradeSystem（P3 — 分支升级系统）

**定位**：处理主动技能的分支选择与升级流程。

**调用关系**：
```
SkillManager.LevelUp(slotIndex)
    └── BranchUpgradeSystem.TryUpgrade(skillData, currentLevel, chosenBranch)
            ├── Lv1→Lv2：触发 BranchChosenEvent → UI 弹窗 → 等待玩家选择
            │       └── 选择后写入 ActiveSkillData.chosenBranch
            └── Lv2→Lv3：根据 chosenBranch 获取对应 Lv3Data → 升级
```

**数据载体**：`ActiveSkillData`（继承 SkillData，附加 `chosenBranch` 运行时字段 + Lv2Left/Lv2Right/Lv3Left/Lv3Right 数据引用）。

**约束**：
- Lv1→Lv2 消耗 1 技能点，Lv2→Lv3 消耗 2 技能点
- 分支选择不可逆
- 冷却/法力消耗受 StatModifierManager 中的 CD/法耗修饰器影响

### 3.4 WeaponSkillLink（P4 — 武器技能联动）

**定位**：监听武器系统的装备/卸下事件，自动管理武器技能在玩家技能池中的存在。

**调用关系**：
```
(武器系统) EquipmentSystem ──EventBus.Trigger(WeaponEquippedEvent)──→ WeaponSkillLink
                                                                    │
                                                            ┌───────┴───────┐
                                                            ▼               ▼
                                                   添加技能到技能池    移除技能从技能池
                                                    (不占 SkillSlot)    (安全移除)
```

**数据载体**：`WeaponSkillData`（继承 SkillData，附加 `weaponType` 标识）。

**边界处理**：
- 组合合成消耗了当前装备武器的技能 → 不同步重新获得，提供 UI 按钮「同步武器技能」
- 卸下/重新装备时 → 自动重新获得

### 3.5 CombinationCraftSystem（P5 — 组合合成系统）

**定位**：合成 UI 的后端逻辑——材料选择、配方匹配、消耗产出。

**调用关系**：
```
CombinationCraftSystem
    ├── GetAvailableMaterials() → 从技能池收集可作材料的技能（主动/武器）
    ├── ValidateRecipe(material1, material2) → 返回配方匹配结果
    │       ├── 等级判定：min(m1.level, m2.level)
    │       └── 配方表匹配 → 返回产出技能 ID 或 null
    ├── Craft(material1, material2) → 消耗材料产出组合技能
    │       ├── 从技能池移除两个材料
    │       ├── 实例化组合技能 → 分配到空闲 SkillSlot
    │       └── 触发 CombinationCraftedEvent
    └── 配送效验：材料不可为组合技能本身，不可为被动技能
```

**数据载体**：`CombinationSkillData`（继承 SkillData，附加组合等级固定 Lv2）。

**配方表**：建议用 ScriptableObject 或 JSON 配置，而非硬编码。

## 四、依赖关系图

### 4.1 文字依赖图

```
P1  StatModifierManager   ◄── 无外部依赖（仅依赖 Unity / EventBus）
    │
    ▼
P2  PassiveEquipManager   ◄── 依赖 P1（装备→AddModifier，卸下→RemoveModifier）
    │
    ▼                                       
P3  BranchUpgradeSystem   ◄── 依赖 P1（CD/法耗查询 StatModifierManager）
    │                      ◄── 依赖 SkillManager（LevelUp 入口）
    │
    ▼
P4  WeaponSkillLink       ◄── 依赖 P2（武器技能作为材料池，与被动共存）
    │
    ▼
P5  CombinationCraftSystem ◄── 依赖 P3（主动技能作为材料）
    │                       ◄── 依赖 P4（武器技能作为材料）
    │
    ▼
P6  调优                   ◄── 依赖 P1~P5
```

### 4.2 依赖规则

1. **下层不得引用上层**：P1 代码中不得出现 P2~P5 的命名空间引用
2. **同一层的 Manager/System 之间可以相互引用**：P3 的 BranchUpgradeSystem 可以调用 SkillManager
3. **EventBus 是所有层级的共享通信层**：P1~P5 之间的跨模块通信通过 EventBus 事件解耦，不直接持有对方实例
4. **UI 代码可以引用任何层级**：UI 是消费者，不参与依赖层级
5. **新增文件的 using 引用规则**：只引入 Framework（EventBus 等）和当前依赖的下层，不引入同层/上层的具体类型

| 文件 | 依赖（直接引用） | 通信方式（解耦） |
|------|-----------------|-----------------|
| Modifier.cs | 无 | — |

| SkillPointManager.cs | EventBus | EventBus.Trigger → UI |
| PassiveSkillData.cs | SkillData | — |
| PassiveEquipManager.cs | PassiveSkillData, StatModifierManager, EventBus | 直接调 StatModifierManager.Add/Remove |
| ActiveSkillData.cs | SkillData | — |
| BranchUpgradeSystem.cs | ActiveSkillData, SkillManager, EventBus | 直接调 SkillManager.LevelUp |

### 6.1 SkillData 基类字段

当前 SkillData 的必备字段（所有子类必须继承或覆盖）：

| 字段 | 类型 | 说明 |
|------|------|------|
| skillName | string | 技能显示名称 |
| description | string | 技能描述（TextArea 2-4行） |
| icon | Sprite | 技能图标 |
| hotkey | KeyCode | 快捷键（Active/Toggle 使用） |
| cooldown | float | 冷却时间（秒） |
| manaCost | float | 法力消耗 |
| type | SkillType | Active / Passive / Toggle |
| category | SkillCategory | Attack / Movement / Defense / Support / Passive |
| unlockLevel | int | 解锁所需等级 |
| castTime | float | 施法时间 |
| skillLevel | int | 当前等级（默认1） |

| sfxClip | AudioClip | 音效（可选） |

**子类扩展模式**（以 BarrierSkillData 为范例）：新增 `[Header("XXX参数")]` 分段，添加子类专属字段。

### 6.2 EventBus 使用约定

**当前 EventBus 实现**：
- 类型安全的静态泛型总线
- `EventBus.Subscribe<T>(handler)` / `EventBus.Unsubscribe<T>(handler)` / `EventBus.Trigger<T>(args)`
- 事件结构体用 `readonly struct`，构造时一次性赋值
- 所有事件在 `Events.cs` 中定义

**生命周期约定**：
- `Subscribe` 在 `OnEnable()` / `Awake()` / `Start()` 中完成
- `Unsubscribe` 在 `OnDisable()` / `OnDestroy()` 中完成
- 场景切换时调 `EventBus.Clear()` 清空所有订阅（当前框架代码中无此调用，需注意）

**跨模块通信约定**：
- Manager/System 之间的直接方法调用仅限同层或下层的强依赖关系
- 跨层通信（如 P5 组合技能完成后通知 HUD）通过 EventBus 解耦
- 回调式 EventBus 不在构造函数中订阅，在 MonoBehaviour 生命周期中订阅

### 6.3 SkillManager 挂载约定

| 条目 | 约定 |
|------|------|
| 挂载位置 | Player GameObject（SkillManager.cs 第 3 行注释说明） |
| 获取方式 | PlayerController.Awake() 中 GetComponent<SkillManager>() |
| SkillSlot 配置方式 | Inspector 拖入 SkillData SO |
| 生命周期 | Awake 初始化，Start 发首次事件，OnPlayerUpdate 每帧更新 |
| 法力管理 | 内置法力池，当前管线的法力计算不含 StatModifierManager 的修饰器（P1 需改造） |
| 冷却管理 | 独立的 cooldownTimers 数组，支持 cdScale 乘法倍率（当前仅受 SynergyConfig 影响） |
| Synergy 联动 | 仅检查所有已装备技能的最低等级，匹配 SynergyConfig.bonuses 数组 |

### 6.4 新增 Manager 挂载约定

### 6.5 资源路径约定

### 6.6 takeDamage 管线当前状态

目前 `PlayerHealth.TakeDamage(amount)` 流程：
```
TakeDamage(amount)
    ├── currentHealth -= amount                // 直减，无闪避/减伤判定
    ├── hitFeedback?.OnTakeDamage()            // 受击反馈（闪红+震屏）
    ├── HitStopController.Instance?.Trigger()  // 命中停顿
    └── EventBus.Trigger(PlayerHealthChangedEvent)
```

**P1 改造目标**（插入两个判定点）：
1. `dodgeChance` 判定：先判定是否闪避 → 闪避则跳过后续步骤
2. `damageReduction` 计算：`actualDamage = incomingDamage × (1 - damageReduction)`
3. 全局 `damageMultiplier` 的影响：由攻击方发出伤害时生效，不在受伤方
