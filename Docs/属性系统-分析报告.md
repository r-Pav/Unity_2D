### 1.3 主属性派生公式

```
┌────────┬──────────────────────────────────────────────────────┐
│ 力量 STR│ 每点: +10 maxHealth, +0.5 hpRegen                     │
│        │ 每10点额外: +1 armor (Bonus，不受%修饰器影响)          │
├────────┼──────────────────────────────────────────────────────┤
│ 智力 INT│ 每点: +10 maxMana, +0.5 mpRegen                       │
│        │ 每10点额外: +5% skillEnhance (Bonus)                  │
├────────┼──────────────────────────────────────────────────────┤
│ 敏捷 AGI│ 每点: +2 attackSpeed, +1% dodgeChance                 │
│        │ 每10点额外: -5% cooldownReduction (Bonus)             │
└────────┴──────────────────────────────────────────────────────┘
```

**Bonus 语义**: 每10点的额外加成不经过修饰器管线——它们是运行时常量加成，不与装备/技能的%加成叠加计算。实现时作为单独的 Flat Modifier 带 priority=999 注入，避免与装备%叠加混淆。

## 二、计算管道

### 2.1 管道总览

```
                      ┌──────────────────────┐
                      │  1. 主属性基础值       │
                      │  (PlayerAttrConfig SO) │
                      └──────────┬───────────┘
                                 │
                      ┌──────────▼───────────┐
                      │  2. 装备主属性加成     │
                      │  (Equipment System)   │
                      └──────────┬───────────┘
                                 │
                      ┌──────────▼───────────┐
                      │  3. 等级/升级点数     │
                      │  (玩家投资 STR/INT/AGI)│
                      └──────────┬───────────┘
                                 │
              ┌──────────────────▼──────────────────┐
              │  4. 主属性终值                        │
              │  finalStr = baseStr + equipStr + points│
              │  finalInt = baseInt + equipInt + points│
              │  finalAgi = baseAgi + equipAgi + points│
              └──────────────────┬──────────────────┘
                                 │
              ┌──────────────────▼──────────────────┐
              │  5. 派生公式计算                      │
              │  derivedMaxHealth = finalStr × 10     │
              │  derivedHpRegen   = finalStr × 0.5   │
              │  derivedArmor     = floor(finalStr/10)×1 │
              │  derivedMaxMana   = finalInt × 10     │
              │  derivedMpRegen   = finalInt × 0.5   │
              │  derivedSkillEnh  = floor(finalInt/10)×0.05│
              │  derivedAtkSpeed  = 100 + finalAgi × 2│
              │  derivedDodge     = finalAgi × 0.01   │
              │  derivedCdReduce  = floor(finalAgi/10)×0.05│
              └──────────────────┬──────────────────┘
                                 │
              ┌──────────────────▼──────────────────┐
              │  6. 注入 StatModifierManager         │
              │  将派生值作为 modifier 注入           │
              │  source="AttrSystem_Derived"          │
              │  priority=-100 (先于装备/技能应用)     │
              └──────────────────┬──────────────────┘
                                 │
              ┌──────────────────▼──────────────────┐
              │  7. 装备/技能/消耗品 修饰器叠加       │
              │  (通过 StatModifierManager 管道)      │
              │  优先序: 派生(-100) → 装备(0) →        │
              │  技能(100) → 消耗品(200)              │
              └──────────────────┬──────────────────┘
                                 │
              ┌──────────────────▼──────────────────┐
              │  8. 最终值                            │
              │  GetFinalValue(derivedBase, statId)   │
              │  公式: base×(1+Σ%) + ΣFlat             │
              │  + 钳制(ClampConfig)                   │
              └──────────────────────────────────────┘
```

### 2.2 关键设计决策

**为什么派生值走 Modifier 注入而不是直接设 baseValue?**

- 项目已有完整的 `StatModifierManager` 管道，包括钳制+事件通知
- 派生值注入后，装备/技能的%和Flat修饰器可以叠加
- 主属性变化时 → 重算派生 → Remove旧source + Add新source → 触发 `StatModifiersChangedEvent` → 下游自动刷新

**Bonus 加成为何用独立 source?**

- Bonus (每10力+护甲等) 使用 source="AttrSystem_Bonus", priority=999
- 与装备的 `source="Equip_X"` 隔离，便于单独移除/重算
- 不与装备%加成混淆——Bonus 是绝对值，不进入百分比叠加链

**attackSpeed 为何基数为 100?**

- 攻击速度现有代码用 `attackSpeedMultiplier` 做倍率 (默认1.0)
- 敏捷的 +2/点 若直接叠加到倍率上会产生爆炸性增长
- 改用基数 100 + AGI×2 作为 attackSpeed 派生值，然后 HUD 显示为攻速数值，实际战斗读取时转换为倍率: `(100 + agiBonus) / 100`

## 三、接口定义

### 3.1 PlayerAttributeSystem (新组件)

```csharp
// 挂 Player GameObject，在 StatModifierManager 之前初始化

/// <summary>
/// 玩家属性系统 — 管理主属性(STR/INT/AGI)与派生属性计算
/// 生命周期: Awake 先于 StatModifierManager 执行
/// </summary>
public class PlayerAttributeSystem : MonoBehaviour
{
    // ── 公开读取 ──

    /// <summary>获取主属性终值(含装备+升级点)</summary>
    public int GetStrength();
    public int GetIntelligence();
    public int GetAgility();

    /// <summary>获取主属性裸值(仅基础+升级点，不含装备)</summary>
    public int GetBaseStrength();

    /// <summary>获取派生属性裸值(公式计算结果，未经过修饰器管线)</summary>
    public float GetDerivedValue(string statId);  // statId: "derivedMaxHealth"等

    // ── 修改接口 ──

    /// <summary>增加升级属性点(str/int/agi 的分配值)</summary>
    public void AddAttributePoint(string attrId);  // "str"/"int"/"agi"

    /// <summary>装备系统调用: 装备变化时更新主属性加成</summary>
    public void SetEquipmentBonus(Dictionary<string,int> attrBonuses);

    /// <summary>装备卸下或清空</summary>
    public void ClearEquipmentBonus();

    /// <summary>完全重算: 主属性→派生→Modifier注入→事件通知</summary>
    public void RecalculateAll();

    // ── 事件 (通过 EventBus) ──
    // PrimaryAttributesChangedEvent → 主属性变化
    // DerivedAttributesChangedEvent → 派生属性重算完成
}
```

### 3.4 事件定义

```csharp
// 追加到 Events.cs

/// <summary>主属性变化事件 — 力量/智力/敏捷任一值变化时触发</summary>
public readonly struct PrimaryAttributesChangedEvent
{
    public readonly int strength;
    public readonly int intelligence;
    public readonly int agility;

    public PrimaryAttributesChangedEvent(int str, int i, int agi)
    {
        strength = str; intelligence = i; agility = agi;
    }
}

/// <summary>派生属性重算完成 — 装备系统/UI 订阅刷新</summary>
public readonly struct DerivedAttributesChangedEvent
{
    public readonly string[] changedStatIds;

    public DerivedAttributesChangedEvent(string[] statIds)
    {
        changedStatIds = statIds;
    }
}
```

## 五、与现有系统的集成点

### 5.1 与 StatModifierManager

- `PlayerAttributeSystem.RecalculateAll()` 调用 `statModManager.AddModifier()` 注入派生值
- 注入时机: Awake 初始化、装备变化、升级加点
- source 命名规范: `"AttrSys_Derived_{statId}"` (派生基础值), `"AttrSys_Bonus_{statId}"` (每10点Bonus加成)

### 5.2 与 PassiveEquipManager

- 不改。被动系统继续通过 `statModManager.AddModifier()` 叠加
- 冲突解决: 派生值 priority=-100，被动 priority=0，被动叠加生效在派生值之上

### 5.3 与装备系统 (P4)

- 装备提供 `bonusStr/bonusInt/bonusAgi` → `PlayerAttributeSystem.SetEquipmentBonus()`
- 装备提供 `statModifiers[]` → 直接注入 `StatModifierManager` (source="Equip_xxx")
- 武器技能走 `WeaponSkillLink`，不涉及属性系统

### 5.4 与 SkillManager

- `manaRegenPerSec` 字段退役，改为读取 `PlayerAttributeSystem.GetDerivedValue("mpRegen")`
- `maxMana` 改为 `statModManager.GetFinalValue(derivedMaxMana, StatId.MaxMana)`
- `cooldownReduction` 叠加到冷却计算: `effectiveCooldown = baseCooldown * (1 - cdReduction) * cooldownMultiplier`

### 5.5 与 Combat 系统

- armor 的伤害减免: `takeDamage = rawDamage - armor` (先减 armor，再走 DamageReduction 倍率)
- 若 armor > rawDamage → 最低伤害 = 1 (保底)
- 建议 armor 减免放在 `PlayerHealth.TakeDamage` 的 `ApplyDamageReduction` 之前

### 5.6 与存档系统

- 需保存: `{assignedStr, assignedInt, assignedAgi}` (玩家分配的点数)
- 基础值来自 SO，装备加成来自装备存档，派生属性运行时计算
- 不需要保存派生值——读档后 `RecalculateAll()` 自动重建

## 七、与 DrawIO 的差异说明

| DrawIO 设计 | 本项目落地方式 | 差异原因 |
|-------------|---------------|---------|
| 属性系统独立节点 | 作为 `PlayerAttributeSystem` 组件挂 Player | 符合项目组件模式 |
| 派生值直接计算 | 派生值注入 `StatModifierManager` 管线 | 复用已有管道+钳制+事件 |
| attackSpeed +2/点 | 基数100 + AGI×2，使用时 /100 转为倍率 | 避免与现有 `attackSpeedMultiplier` 语义冲突 |
| 装备属性走"属性+技能"节点 | 装备分两路: 主属性→AttributeSystem, statMods→ModifierManager | 清晰的数据来源追踪 |
| 冷却缩减 -5%/10敏 | 作为独立的 `cooldownReduction` 叠加到 `cooldownMultiplier` | 两段冷却: 基础缩减 + 倍率修饰 |
| enemy/player 死亡掉落 | 留装备系统接口, 本报告不展开 | DrawIO 侧注, 非属性系统核心 |
